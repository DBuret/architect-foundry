# Axe sources

À lire après `SKILL.md`, pour une revue sur cet axe seulement.

- Toute affirmation sur un éditeur ou un produit porte une source, ou une
  xref vers l'hypothèse du registre qui la couvre.
- Une déduction non sourcée (fonctionnement supposé d'un produit, par
  exemple) doit être une hypothèse ou un point ouvert du registre, citée par
  xref. Signale toute déduction présentée comme un fait.
- Vérifie dans la base projet chaque affirmation qui invoque un entrant
  écrit du projet (note, présentation, compte rendu, livrable amont), et
  dans la base multi-projets chaque affirmation qui invoque une norme, une
  réglementation ou un ouvrage de référence. Donne à chacune un verdict de
  `recherche-rag`. Une affirmation rattachée à une indication orale ou à un
  écrit hors base se traite selon `recherche-rag`, « Sources hors base ».
- Vérifie d'abord les affirmations qui soutiennent un critère de décision ou
  la recommandation, puis les chiffres, puis le reste. Si le périmètre est
  trop large pour tout vérifier, dis ce qui reste « non vérifié » au lieu
  d'échantillonner en silence.
- Si tu disposes d'une extension de recherche web, vérifie aussi les
  affirmations techniques sur un produit ou un éditeur contre sa
  documentation publique (comportement réel d'un protocole ou d'un
  composant, limites annoncées par l'éditeur). N'utilise la
  recherche web que pour du contenu déjà public ; n'y envoie jamais de
  contenu interne à l'entreprise (noms de projets, architecture cible, chiffres),
  ni un extrait des bases de connaissances. Marque chaque constat issu du
  web comme tel, distinctement d'un constat issu d'une base, et cite l'URL.
